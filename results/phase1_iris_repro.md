## Reading

- **The gate passes.** Q4_K_M is detectable from 16-bit strings at 0.6B, on length-ablated features, with the 2.5th percentile of q above alpha, and the independent fp16 run stays at the floor. The content-only tell rate (0.39) is within IRIS's band (0.37 [0.17, 0.51]).
- **Full-feature q is higher than IRIS's** (0.56 vs 0.42). Plausible causes: a different q4 build (our Q4_K_M vs Ollama's), a different runtime, and our untruncated sampler, which lets length and format vary more. Length-sensitive features gain from that. This is why content-only is the primary metric.
- **The integer probe is uninformative here for a reason IRIS did not report.** The 0.6B model echoes the prompt in 72–97% of responses and runs to the 48-token cap; the first-integer parser then returns the "1" from "between 1 and 100" in 95–99% of rows for every variant. So the null result is a parser artifact, not evidence about quantization. IRIS's parser has the same first-integer rule. For Phase 3 the number parser must take the answer, not the echo (e.g. last integer, or the integer after the final colon/bold marker), and parse-failure must be flagged when the response echoes the prompt.
- **Data quality:** 0 request errors in 1,300 requests; 16-bit probe parse success 99.5–100%; the model produces exactly 16 symbols only about 10% of the time (median 22), so length ablation matters.

**Runtime confound test** (`phase1_backend_confound.json`): f16 on CPU vs f16 on CUDA, disjoint
seeds, 16 bits: q = 0.05 [0.01, 0.11] full, 0.06 [0.01, 0.11] content-only, AUROC 0.53. The two
backends of this build are indistinguishable by this detector, so backend is not a confound here.
(A first attempt with shared seeds gave AUROC 0.19, below chance, because the same seed produces
identical text on CPU and CUDA 94% of the time and the duplicates leaked across train and test.)

**Seed-sharing caveat on the main result.** The f16 reference and Q4_K_M pools above also shared
seeds (same run id). 9% of same-seed pairs are byte-identical between f16 and Q4_K_M on 16 bits
(0% on the integer probe), which pushes q *down*. The gate result is therefore conservative. From
here on every pool has its own seed range (prereg §4; `collect/runner.py`).
